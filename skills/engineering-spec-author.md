# Engineering spec author

Use this skill when you need to write a clear engineering specification for product or platform work.

## When to use

- turning a product idea into an implementation brief
- defining requirements for engineering delivery
- preparing handoff from product to engineering
- writing technical scope for feature work

## Goal

Produce a concise, implementation-ready spec that helps engineering understand:

- the problem
- the desired user outcome
- the scope
- constraints
- edge cases
- acceptance criteria

## Standard structure

### 1. Summary
State the feature or problem in plain language.

### 2. Problem statement
Describe the user problem, business problem, or operational need.

### 3. Goals and non-goals
- Goals: what success looks like
- Non-goals: what is explicitly out of scope

### 4. User scenarios
Describe the most relevant user journeys or operational use cases.

### 5. Functional requirements
List what the system must do.

### 6. Technical considerations
Call out constraints such as:

- data dependencies
- platform constraints
- integration points
- performance considerations
- privacy or security concerns

### 7. Edge cases and failure states
Document likely edge cases and what should happen.

### 8. Acceptance criteria
Write clear, testable criteria.

### 9. Open questions and dependencies
Call out unresolved questions, assumptions, and dependencies.

## Quality bar

A good engineering spec should:

- be specific enough for implementation
- minimize ambiguity
- capture user and business outcomes
- identify dependencies and constraints
- be easy for engineering to evaluate against

## Prompt pattern

"Write an engineering spec for this feature. Start with the problem and desired outcome, define the scope and non-goals, provide functional requirements, include key technical considerations and edge cases, and end with testable acceptance criteria and open questions."
