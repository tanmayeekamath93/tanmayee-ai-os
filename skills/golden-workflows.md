# Golden workflows

This file captures the highest-value workflows that you should use repeatedly without re-explaining context every time.

## Golden workflow 1: Product brief to action

Use when you need to turn a rough idea into a concrete plan.

### Prompt

"Use the personal AI operating instructions and the PM + research workflow. Turn this rough input into a clear brief with the problem, context, key findings, recommendation, risks, and next actions. Keep the output concise and decision-oriented."

## Golden workflow 2: Research synthesis

Use when you need to turn notes, calls, or scattered materials into clear insight.

### Prompt

"Summarize the inputs into key themes, customer signals, opportunities, and risks. Separate facts from assumptions, highlight implications, and recommend the next best action. Format as a clean research brief suited for stakeholder review."

## Golden workflow 3: Engineering handoff

Use when you need to go from product direction to implementation-ready scope.

### Prompt

"Write an engineering spec for this feature. Include problem statement, goals and non-goals, user scenarios, functional requirements, technical considerations, edge cases, acceptance criteria, and any open questions or dependencies. Keep it clear and implementation-ready."

## Golden workflow 4: Leadership-ready release summary

Use when you need to prepare a leadership update from feature usage and customer input.

### Prompt

"Create a leadership-ready HTML summary of customer learning and feature usage for this release. Include executive summary, key takeaways, usage snapshot, customer learning, implications for leadership, and recommended next steps. Use concise, business-oriented language and an easy-to-scan layout."

## Golden workflow 5: Quality check before sending

Use when you want to validate whether an output is strong enough.

### Prompt

"Review this draft against the AI quality rubric. Assess relevance, clarity, actionability, evidence quality, and completeness. Provide a score and call out what should be improved before it is used or shared."
